# 微信小游戏客户端开发计划

| 项目 | 内容 |
| --- | --- |
| 计划版本 | v1.0 |
| 适用工程 | 微信小游戏客户端 |
| 需求基线 | `PRD.md` v1.1 |
| 总计划 | `DEVELOPMENT_PLAN.md` |
| 接口基线 | `INTEGRATION_CONTRACT.md` |
| 开发模式 | 本人独立开发，AI 辅助编码与测试 |
| 基线周期 | 与总计划一致，全职约 24 周 |

> 本文只描述客户端工程。服务端规则、角色分配、AI 策略和私有信息判定不在此工程实现。客户端通过 `INTEGRATION_CONTRACT.md` 调用服务端，并展示服务端允许其看到的状态。

---

## 1. 客户端范围

### 1.1 负责内容

- 微信小游戏启动、登录、匿名账号态和页面导航。
- 首页、房间配置、背景与角色预览、等待房间。
- 身份揭示、对局桌面、夜晚行动、白天发言、投票、结算和复盘。
- 文本输入、语音录制、上传、转写结果编辑与确认。
- WebSocket 连接、事件排序、断线重连、快照同步。
- 自己的游戏角色和合法私有信息展示。
- 真机适配、交互反馈、错误提示、客户端埋点和性能。
- 微信小游戏构建、体验版发布和审核材料准备。

### 1.2 不负责内容

- 游戏角色分配、技能合法性和胜负判定。
- 其他玩家真实游戏角色的判定或存储。
- DS API、ASR 密钥和任何服务端凭证。
- AI 策略、Agent 编排、Prompt 和私有信息过滤。
- 用本地状态替代服务端权威状态。
- 直接保存原始录音作为长期业务数据。

### 1.3 客户端原则

1. 服务端快照是唯一权威，客户端状态用于展示和短期交互。
2. 客户端只展示自己的游戏角色；其他人的游戏角色在结算前不得出现。
3. 席位号可用于座位布局，但 AI 发言区域必须以背景角色名展示。
4. 页面刷新、切后台或重连后能从服务端快照恢复。
5. 交互必须覆盖加载、成功、失败、超时、无权限和断网状态。
6. 任何模型或语音异常不得导致 UI 卡死。

## 2. 技术结构

### 2.1 技术基线

- 微信小游戏原生 TypeScript + Canvas 启动层。当前工程不依赖 Cocos；当正式视觉方案需要复杂场景、动画和资源管线时，再在阶段 C0 通过 ADR 决定是否引入 Cocos。
- `wx.login`、`wx.getRecorderManager`、`wx.uploadFile`、`wx.connectSocket` 等原生能力。
- 使用轻量状态管理维护房间、对局、连接和输入状态。
- 服务端事件通过统一 WebSocket 事件层分发，不把网络请求散落在页面中。
- 本地只保存登录态、未提交草稿、音量和界面偏好，不保存完整游戏真相。

### 2.2 建议目录

```text
assets/
  scenes/
    Boot
    Lobby
    Game
  scripts/
    app/             启动、路由、配置、生命周期
    auth/            微信登录和会话恢复
    network/         HTTP、WSS、重试、事件分发
    room/            房间创建、加入、配置、等待
    game/            对局展示、阶段、席位、投票
    speech/          录音、上传、转写文本编辑
    ui/              通用组件、弹窗、错误提示
    telemetry/       客户端事件和错误上报
  resources/         图标、字体、声音和临时视觉资源
tests/               状态层单测和协议解析测试
```

### 2.3 核心状态

| 状态域 | 主要内容 |
| --- | --- |
| AuthState | 登录中、已登录、会话失效 |
| RoomState | 房间 ID、席位、准备状态、配置版本 |
| GameState | 对局 ID、阶段、轮次、自己的游戏角色、合法操作、公共时间线 |
| ConnectionState | 未连接、连接中、在线、重连中、需全量同步 |
| SpeechDraft | 文本草稿、录音中、上传中、转写中、待确认、提交失败 |
| UiState | 当前页面、弹窗、加载和错误态 |

## 3. 里程碑总览

详细总计划见 `DEVELOPMENT_PLAN.md`。客户端的九个阶段如下：

| 阶段 | 周次 | 客户端目标 | 主要交付 |
| --- | --- | --- | --- |
| C0 | W1～W2 | 工程、网络、页面骨架与构建链路 | 可构建、可连服务端的空客户端 |
| C1 | W3～W4 | 登录、首页、创建房间和角色配置 | 可配置合法房间 |
| C2 | W5～W7 | 游戏桌面 UI 和状态展示 | 可通过服务端快照展示完整棋盘 |
| C3 | W8～W10 | 单人完整对局交互 | 1 名真人 + 多名 AI 可玩通 |
| C4 | W11～W14 | 背景输入、阵容预览、单人和多 Agent 展示 | 双身份与角色名表达可视化 |
| C5 | W15～W16 | 录音、ASR、文本编辑 | 语音输入闭环 |
| C6 | W17～W19 | 好友房、邀请、实时同步和重连 | 多人混合局客户端可完成 |
| C7 | W20～W22 | 性能、异常、真机、无障碍和埋点加固 | 达到发布候选质量 |
| C8 | W23～W24 | 构建、回归、体验版和灰度准备 | 微信客户端发布候选 |

## 4. 阶段 C0：工程与连接骨架

**周期**：W1～W2。
**联调节点**：CP0。

### 4.1 实现任务

- [ ] 建立微信小游戏原生 TypeScript 工程，配置 `game.js`、`game.json`、微信开发者工具配置、TypeScript 构建和基础包设置。
- [ ] 建立 Boot、Lobby、Game 三个基础场景及路由。
- [ ] 实现安全区、横竖屏策略、屏幕尺寸适配和统一字体配置。
- [ ] 建立 HTTP 请求封装：基地址、超时、统一错误结构、登录态注入。
- [ ] 建立 WSS 封装：连接、心跳、断线检测、重连退避、事件回调。
- [ ] 建立开发环境健康检查页，显示服务端版本和连接状态。
- [ ] 建立统一 Loading、Toast、确认框和阻断式错误弹窗。
- [ ] 建立日志工具，禁止输出 token、openid、完整发言和录音路径。
- [ ] 添加本地 Mock 模式，在网络层切换固定响应，便于独立开发 UI。
- [ ] 配置开发、测试、生产 API/WSS 地址，但不在包内写入密钥。
- [ ] 建立 Windows 本地构建和微信开发者工具导入流程。
- [ ] 建立客户端单元测试环境，优先覆盖状态转换和协议解析。

### 4.2 契约接入

- `GET /v1/health`。
- WSS 连接鉴权和 `server.hello` 事件。
- 统一响应 `code/message/request_id/data`。
- WebSocket 事件信封 `event_id/sequence/server_time/type/payload`。

### 4.3 交付物

- 可启动、可切换场景的微信小游戏。
- 可运行的 HTTP/WSS 网络层。
- UI 基础组件和错误反馈组件。
- 开发环境连接页。
- 客户端构建说明。

### 4.4 阶段门

- 微信开发者工具和至少一台真机可打开客户端。
- 客户端能完成服务端健康检查和一次 WSS 测试事件。
- 关闭服务端时显示可重试错误，不出现白屏或无限 Loading。
- 包内不存在任何服务端密钥。

## 5. 阶段 C1：登录与房间配置

**周期**：W3～W4。
**联调节点**：CP1。

### 5.1 登录和首页

- [ ] 启动后调用 `wx.login` 获取一次性登录码并换取服务端会话。
- [ ] 实现登录中、会话过期、自动续期和重新登录。
- [ ] 首页展示单人开局、创建好友房、加入好友房、继续对局和最近战绩。
- [ ] “加入好友房”在服务端能力完成前通过功能开关隐藏。
- [ ] 无历史对局时突出单人开局，不展示空状态堆积。

### 5.2 创建房间与配置

- [ ] 单人/好友房模式切换。
- [ ] 总人数 6～12 人选择，默认 9 人。
- [ ] 单人模式 1 名真人，其余 AI 席位自动计算。
- [ ] 好友房真人/AI 席位数量配置。
- [ ] 游戏角色数量加减：狼人、村民、预言家、女巫、猎人。
- [ ] 推荐模板：6、7、8、9、10、11、12 人。
- [ ] 实时显示“已配置人数 / 总人数”。
- [ ] 明确提示人数不匹配、无狼人、无非狼人、唯一角色超量。
- [ ] 配置修改请求防抖、保存中、保存成功、失败重试。
- [ ] 保存房间配置版本，收到版本冲突时重新拉取。
- [ ] 未开局房间退出后可在首页继续进入。

### 5.3 契约接入

- `POST /v1/auth/wechat`。
- `POST /v1/rooms`。
- `GET /v1/rooms/{room_id}`。
- `PATCH /v1/rooms/{room_id}/config`。
- `room.updated`。

### 5.4 交付物

- 完整登录态与首页。
- 单人/好友房配置界面。
- 角色配置与错误提示组件。
- 房间配置 API 接入。
- 基础 E2E 测试。

### 5.5 阶段门

- 真机可创建 6～12 人房间并保存合法配置。
- 非法配置在客户端有即时提示，同时服务端拒绝也显示正确原因。
- 弱网重复保存不会创建重复房间或重复席位。
- 清空本地缓存后可恢复登录态和未开局房间。

## 6. 阶段 C2：游戏桌面骨架

**周期**：W5～W7。
**联调节点**：CP2。

### 6.1 桌面布局

- [ ] 环形或双列席位布局，支持 6～12 人。
- [ ] 每个席位显示席位号、昵称、背景角色、存活状态、说话状态、投票状态和 AI 标识。
- [ ] 当前阶段、轮次、剩余时间和“我的身份”入口。
- [ ] 公共时间线固定在可滚动区域，支持自动滚到底和手动回看。
- [ ] 私有信息入口必须二次点击查看，关闭后不保留屏幕提示。
- [ ] 所有游戏角色展示均来自服务端裁剪后的当前玩家快照。

### 6.2 身份与阶段展示

- [ ] 身份揭示页展示“我的背景角色”和“我的游戏角色”。
- [ ] 不同游戏角色展示不同能力说明，但不展示其他玩家职业。
- [ ] 夜晚阶段视图：可行动、等待他人、结算中。
- [ ] 白天阶段视图：死亡公告、遗言、发言顺序、公共时间线。
- [ ] 投票阶段视图：存活候选、已确认、统一公布结果。
- [ ] 已死亡状态只显示允许查看的公共信息和遗言入口。

### 6.3 状态与错误

- [ ] 实现快照渲染，不依赖本地拼装历史事件得到完整状态。
- [ ] 对 `sequence` 缺口触发全量同步。
- [ ] 对手动刷新、离线、重新连接、服务端维护显示独立状态。
- [ ] 对无权限、阶段已结束、目标不合法等错误显示明确说明。

### 6.4 契约接入

- `GET /v1/games/{game_id}/snapshot`。
- `game.started`、`phase.changed`、`turn.started`、`player.out`。
- 玩家视角的 `GameSnapshot` 和 `self_game_role` 字段。

### 6.5 交付物

- 对局桌面场景。
- 身份揭示、公共时间线和阶段视图。
- 基于快照的客户端状态机。
- 桌面 UI 组件测试和协议解析测试。

### 6.6 阶段门

- 使用服务端测试快照可以展示 6、9、12 人桌面。
- 客户端不会在公共区域显示其他玩家的游戏角色。
- 快照缺失或版本过旧时能进入安全错误状态，不崩溃。
- 页面切换到后台再回来，能够重新读取当前快照。

## 7. 阶段 C3：单人完整对局

**周期**：W8～W10。
**联调节点**：CP3。

### 7.1 对局交互

- [ ] 创建单人局后进入身份揭示和首夜。
- [ ] 夜间仅展示当前玩家合法技能和合法目标。
- [ ] 无合法目标时展示“本回合无操作”，可提交跳过。
- [ ] 提交行动后显示等待状态，不自行假设行动成功。
- [ ] 白天文本输入、字数限制、发送和不可撤回提示。
- [ ] AI 思考、流式发言和完成状态。
- [ ] AI 发言气泡显示背景角色名，不显示号码式指代。
- [ ] 投票选择、确认、修改（截止前）、统一票型公布。
- [ ] 平票重投、放逐、遗言、猎人选择和结算。
- [ ] 结算页展示全员背景角色、游戏角色、阵营和胜负。
- [ ] 对局结束后提供基础微信战绩分享；不能分享未结束局私有身份。
- [ ] 基础复盘按时间顺序展示公开事件和 AI 文本。

### 7.2 WebSocket 与恢复

- [ ] 处理 `private.action_result`，只应用到当前席位。
- [ ] 处理 `speech.delta` 的分段展示和最终文本去重。
- [ ] 断线后拉取快照并恢复到当前阶段。
- [ ] 重复事件不重复插入时间线、不重复投票。
- [ ] 超时自动弃权后显示明确状态。

### 7.3 契约接入

- `POST /v1/games/{game_id}/actions`。
- `POST /v1/games/{game_id}/speeches`。
- `speech.delta`、`speech.completed`、`vote.requested`、`vote.result`、`game.ended`。
- `GET /v1/games/{game_id}/replay`。

### 7.4 交付物

- 可完整操作的 6～12 人单人客户端。
- AI 文本流式展示。
- 投票、结算和基础复盘页面。
- 断线恢复和事件去重。

### 7.5 阶段门

- 通过客户端可独立完成 6、9、12 人单人局。
- AI 文本在客户端始终以背景角色名展示。
- 断线重连不丢失身份或当前阶段。
- DS 降级、AI 超时和语音未实现时，文字对局仍可完成。
- iOS、Android 各至少 2 台真机完成整局。

## 8. 阶段 C4：背景、角色阵容与多 Agent 展示

**周期**：W11～W14。
**联调节点**：CP4。

### 8.1 背景输入

- [ ] 背景描述输入 1～200 字，实时显示字数。
- [ ] 我的背景角色输入 1～20 字，可选“随机分配”。
- [ ] 提供明显的输入示例，但不强制使用预置世界观。
- [ ] 内容安全失败、生成中、超时和失败状态。
- [ ] 生成最多等待 15 秒，期间允许取消。

### 8.2 角色阵容预览

- [ ] 显示角色名、简短性格和示例语气。
- [ ] 标记“我的背景角色”。
- [ ] AI 角色去重并以网格或列表展示。
- [ ] 删除候选角色后触发补位。
- [ ] 重新生成最多 3 次。
- [ ] 阵容锁定前明确提示“开局后不可修改”。
- [ ] 生成失败时提供重试和可用兜底阵容。

### 8.3 双身份和对局展示

- [ ] 身份页清楚区分“我的背景角色”和“我的游戏角色”。
- [ ] 阵容与游戏角色分配完成后刷新对局快照。
- [ ] AI 角色名在各阶段 UI 中保持一致。
- [ ] 真人发言含席位号时正常显示；AI 文本仍只用背景角色名。
- [ ] 长角色名和重名防冲突的名称布局适配。
- [ ] 复盘展示 AI 发言对应的背景角色，不展示内部策略。

### 8.4 契约接入

- `POST /v1/rooms/{room_id}/theme-drafts`。
- `ThemePackResponse`、`CharacterCard`。
- `speech.completed` 中的 `speaker_reference_name`。
- 生成错误码：`THEME_MODERATION_BLOCKED`、`THEME_GENERATION_TIMEOUT`、`THEME_GENERATION_FAILED`。

### 8.5 交付物

- 背景和指定角色输入页。
- 角色阵容预览、删除、补位和重新生成。
- 双身份身份页。
- 人物名展示和对局排版适配。

### 8.6 阶段门

- 可通过客户端生成并确认至少三种背景的角色阵容。
- 用户指定角色不会被 AI 占用。
- 12 人局角色名不重叠、不溢出、不遮挡。
- AI 发言中不出现席位编号，席位号只出现在座位 UI。
- 生成失败时用户能继续操作或使用兜底阵容。

## 9. 阶段 C5：语音转文字

**周期**：W15～W16。
**联调节点**：CP5。

### 9.1 录音交互

- [ ] 文字/录音模式切换。
- [ ] 首次录音说明用途、隐私和保存策略，再请求麦克风权限。
- [ ] 授权拒绝时提供设置入口和“继续打字”。
- [ ] 录音计时、音量波形、取消和重新录制。
- [ ] 单次 1～60 秒限制，过短和静音提示。
- [ ] 录音结束前不自动上传或发送。
- [ ] 对局超时或阶段结束立即停止录音并禁止提交。

### 9.2 转写与确认

- [ ] 通过服务端创建 ASR Session。
- [ ] 使用 `wx.uploadFile` 上传音频，显示上传进度。
- [ ] 上传失败、ASR 超时和内容审核失败分别提示。
- [ ] 转写结果填入可编辑文本框。
- [ ] 用户可以完全修改、重新录音或改为打字。
- [ ] 只有点击确认后调用发言提交接口。
- [ ] 删除本地临时音频路径，不保存到对局记录。
- [ ] 转写后至少保留 10 秒编辑窗口，具体倒计时以服务端为准。

### 9.3 契约接入

- `POST /v1/asr/sessions`。
- `POST /v1/asr/sessions/{session_id}/audio`。
- `AsrSessionResponse`。
- `POST /v1/games/{game_id}/speeches`。

### 9.4 交付物

- 录音界面和权限流程。
- 上传、转写、编辑、确认完整流程。
- 录音异常和降级处理。

## 13. 客户端测试矩阵

| 类型 | 重点 |
| --- | --- |
| 状态单测 | Auth、Room、Game、Connection、SpeechDraft 状态转换 |

必须单独覆盖：

1. AI 发言首次指代显示背景角色名。
2. AI 发言不显示“几号”“N 号”“N 位”。
3. 真人发言可以包含席位号，但界面不会把它自动改写成“系统事实”。
4. 普通玩家界面无法获取其他玩家游戏角色。
5. DS 流式发言失败时显示兜底文本而不是空白。
6. ASR 失败时仍可手动输入。
7. 断线重连后只应用一次投票和一次 AI 发言。

## 14. 客户端完成定义

满足以下条件时，客户端工程达到 P0 交付标准：

- 完整覆盖单人 AI 对局和真人/AI 混合好友房。

- 服务端不可用、模型超时、ASR 失败和断线都有可操作反馈。
- 所有私有游戏角色只在本人接口和结算后公开。
- AI 发言在客户端始终用背景角色名指代玩家。
- 主要 iOS/Android 真机通过回归。
- 包里没有 DS/ASR/数据库密钥。
- 微信小游戏体验版可以独立安装并完成核心流程。
