## 1. 已完成功能

### 1.1 工程与基础服务

- 客户端与服务端独立工程。
- 服务端 HTTP 健康检查 `GET /v1/health`。
- WebSocket 占位连接 `WS /v1/ws`、首帧握手和心跳响应。
- Vitest 单元与接口测试。
- SQLite 文件数据库和 PostgreSQL 适配器。
- Docker Compose PostgreSQL 本地配置。

### 1.2 微信登录

- 客户端调用 `wx.login()` 获取 code。
- 服务端支持 Mock 登录和真实微信 `jscode2session` 登录。
- 微信 `openid` 仅保存在服务端，不返回客户端。
- 内部用户 UUID 和可展示的 `public_id`。
- 不获取、不承诺保存用户微信号。
- 首次登录设置昵称。
- Opaque 会话 Token；数据库只保存 Token 的 SHA-256 哈希。
- 客户端启动时自动恢复登录状态。

接口：

```text
POST  /v1/auth/wechat
GET   /v1/me
PATCH /v1/me/profile
```

### 1.3 客户端首页

- 暗夜悬疑风格的登录页和首页。
- 微信原生胶囊安全区适配。
- 用户昵称和 `public_id` 展示。
- 单人开局入口。
- 好友房和最近对局占位。
- 点击单人开局进入房间配置。

### 1.4 单人房间配置

- 支持 6～12 人，默认 9 人。
- 切换人数时自动套用推荐角色模板。
- 可调整狼人、村民、预言家、女巫、猎人数量。
- 客户端和服务端双重校验。
- 创建成功展示房间编号、玩家人数和角色摘要。
- 房间及席位保存到数据库。
- 客户端保存活动房间 ID，登录后通过 GET 自动恢复未开始房间。
- 首页提供“继续房间”入口。
- 支持返回配置页修改人数和角色，并通过 PATCH 保存。
- 房间配置使用版本号防止并发覆盖。

接口：

```text
POST /v1/rooms
GET  /v1/rooms/:room_id
PATCH /v1/rooms/:room_id/config
```

数据库表：

```text
users
user_sessions
rooms
room_seats
games
```

### 1.5 规则引擎与游戏桌面

- 固定随机种子的角色分配。
- 狼人、村民、预言家、女巫、猎人基础状态。
- 夜晚狼人袭击、预言家查验、女巫解药/毒药。
- 猎人被狼人击杀或被放逐后触发猎枪。
- 放逐投票、一次平票重投、无有效票流局。
- 屠边胜负判定。
- 非真人席位由随机合法机器人自动行动。
- 游戏状态和事件以 JSON 持久化，状态版本乐观锁。
- 玩家快照只公开自己的游戏角色；终局后揭开全部角色。
- 白天按顺序逐人发言，第一日随机首位，后续按存活席位轮转。
- 真人发言支持 1～300 字文本；60 秒截止后可通过 tick 自动跳过。
- AI 席位当前使用固定短句自动发言，待阶段 3 替换为多 Agent。
- 客户端游戏桌面展示身份、4 列席位、阶段、事件和基础行动。
- 支持行动目标选择、狼人袭击、查验、女巫用药、猎人开枪和投票。
- 支持白天文本发言输入、倒计时和跳过。
- 终局显示阵营胜负、全员身份，并可分页查看全部对局事件。
- 进行中的游戏 ID 保存在本地，可重新进入并恢复。

接口：

```text
POST /v1/rooms/:room_id/start
GET  /v1/games/:game_id/snapshot
POST /v1/games/:game_id/actions
POST /v1/games/:game_id/tick
```
